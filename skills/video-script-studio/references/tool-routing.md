# 外部能力路由

## 目的

为搜索、解析、转录和文件读取选择可验证的能力，并在能力不足时显式降级或停止。外部工具只获取材料，不替代创意决策。

## 必需输入

- 待回答的问题、所需来源等级、时效和正文完整性要求。
- 当前能力清单，包括已安装专业 Skill、基础网页工具、本地文件读取器和用户可补充的材料。
- 数据敏感性、登录限制、付费墙和高风险领域要求。

## 执行步骤

1. 调用前检查能力清单，不假定某个工具存在。
2. 优先使用与媒介匹配的专业 Skill：搜索、网页正文、字幕/转录、PDF、文档或表格解析。
3. 专业 Skill 不可用时，只有在基础工具能满足正文与来源契约时才降级；记录降级原因和缺失能力。
4. 每条结果记录 `provenance`、`accessed_at`、`capture_status` 和 `body_status`。搜索摘要只能标为 `search-snippet`，不能标为完整正文。
5. 基础工具也无法取得可用正文时，请用户提供文件、字幕或替代来源；事实主张仍无支持时停止该主张，不得编造结果。

## 输出契约

输出能力选择、调用目的、实际取得的来源、访问日期、正文完整性、失败原因和下一步。URL 或文件来源必须能直接进入 `sources.md` 的严格字段；工具推断与来源原文分开记录。

## 拒绝条件

- 工具不存在却被描述为已经调用。
- 只有搜索摘要，却准备把内容写成已核实事实。
- 来源身份、日期或正文状态无法保留。
- 登录、版权或隐私边界不允许继续；此时明确停止，不静默绕过。

## 下一阶段交接

把可读取的正文、完整性状态和失败记录交给 [调研工作流](research.md)。若停止，保留当前项目状态，并明确列出用户提供什么材料后可以恢复。
